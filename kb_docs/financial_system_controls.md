# Illustrative financial-system control design prompts

This seed material is an internal design checklist for prototyping only. It is not a regulation, an authoritative interpretation, or a substitute for the institution's approved policies.

## Identity and access

For sensitive financial workflows, teams should define identity proofing, authentication, authorization, least privilege, segregation of duties, privileged access review, and auditable access changes. Assign a control owner and specify measurable verification evidence.

## Customer data handling

Document the purpose for collecting customer information, data minimization, consent where applicable, retention periods, secure deletion, access restrictions, encryption expectations, and incident handling. Confirm applicable privacy obligations with counsel and the accountable privacy function.

## Auditability and recordkeeping

Identify decisions and material changes that need an audit trail. Specify event fields, integrity protection, retention ownership, monitoring, and access controls. Verify recordkeeping requirements against current primary sources and institution policy.

## Resilience and recovery

Set business-approved availability, recovery time, and recovery point objectives. Define backup protection, restore testing, incident escalation, and evidence of recovery exercises.

## Verification and release governance

Link each approved requirement to acceptance criteria, test evidence, a business owner, and an accountable release gate. Require independent review for high-impact security, privacy, and compliance controls.
